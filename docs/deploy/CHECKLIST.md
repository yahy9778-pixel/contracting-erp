# قائمة التحقق قبل الإطلاق

لا يُفتح النظام للموظفين حتى تكون كل البنود ✅. انسخ القائمة في ملاحظة وعلّم عليها.

## الخادم

- [ ] Ubuntu 24.04 محدّث، والتحديثات الأمنية التلقائية مفعلة (`unattended-upgrades`)
- [ ] الدخول بمفتاح SSH فقط: `PasswordAuthentication no` و`PermitRootLogin no`
- [ ] الجدار الناري مفعل ولا يسمح إلا بـ 22 و80 و443 (`sudo ufw status`)
- [ ] `fail2ban` يعمل (`sudo systemctl status fail2ban`)
- [ ] قاعدة البيانات غير مكشوفة: `docker compose ps` لا يُظهر منفذا منشورا لخدمة `db`

## النطاق وHTTPS

- [ ] سجل A يشير إلى الخادم
- [ ] `https://النطاق` يفتح بقفل سليم في المتصفح
- [ ] `http://النطاق` يتحول تلقائيا إلى `https://`
- [ ] تقييم A أو أعلى في [SSL Labs](https://www.ssllabs.com/ssltest/)

## الأسرار والإعدادات

- [ ] `SESSION_SECRET` عشوائي 32 حرفا أو أكثر، ومولد بـ `openssl rand`
- [ ] `POSTGRES_PASSWORD` عشوائي
- [ ] `ANTHROPIC_API_KEY` مفتاح خاص بالخادم، بحد إنفاق شهري في console.anthropic.com
- [ ] صلاحية `.env` هي `600`، وغير موجود في GitHub
- [ ] نسخة من كل الأسرار في مدير كلمات مرور

## البيانات والحسابات

- [ ] لم يُشغّل `db:seed` على الخادم (لا توجد حسابات `@company.local`)
- [ ] حساب المالك أُنشئ بـ `prisma/bootstrap.ts` بكلمة مرور قوية
- [ ] إن نُقلت بيانات من SQLite: السكربت أنهى بـ "الأعداد مطابقة للمصدر"، وراجعت عينة (مشروع، مستخلص، رصيد البنك)
- [ ] كل موظف له حساب باسمه ودوره الصحيح، ولا توجد حسابات مشتركة
- [ ] حد اعتماد أوامر الشراء `PO_APPROVAL_LIMIT` مضبوط حسب سياسة الشركة

## النسخ الاحتياطي

- [ ] يوجد ملف في `backups/` بتاريخ اليوم
- [ ] النسخ يصل إلى التخزين الخارجي (`rclone ls offsite:erp-backups`)
- [ ] **جرّبت الاستعادة فعلا** على نسخة (انظر [RUNBOOK](RUNBOOK.md#تمرين-الاستعادة)) وفتحت النظام بعدها

## الاختبارات

- [ ] CI أخضر على آخر commit في `main`
- [ ] `npm run smoke` على النطاق: كل البنود ✓
- [ ] `npm run loadtest` بـ 20 مستخدما: p95 أقل من 1000ms وأخطاء أقل من 1%
- [ ] تجربة يدوية لدورة كاملة بحساب حقيقي: تقرير يومي ← اعتماده ← مستخلص ← اعتماده ← قيد في دفتر اليومية
- [ ] تجربة الوكيل الذكي على تقرير يومي واحد (يتحقق أن مفتاح Claude يعمل)
- [ ] الدخول من جوال على شبكة الجوال (ليس شبكة المكتب)

## المراقبة

- [ ] مراقبة خارجية على `https://النطاق/api/health` كل 5 دقائق مع تنبيه بالبريد أو الجوال (UptimeRobot أو Better Stack، المجاني يكفي)
- [ ] تنبيه من مزود الخادم عند تجاوز القرص 80%

## النشر التلقائي (إن فُعّل)

- [ ] أسرار `DEPLOY_*` ومتغير `DEPLOY_ENABLED=true` مضبوطة
- [ ] حماية فرع `main` تشترط نجاح CI
- [ ] تشغيل يدوي واحد ناجح لـ Deploy من تبويب Actions

## يوم الإطلاق

- [ ] نسخة احتياطية يدوية قبل فتح النظام: `sh scripts/backup-now.sh`
- [ ] إرسال رابط النظام وبيانات الدخول لكل موظف على حدة، مع طلب تغيير كلمة المرور من صفحة الحساب
- [ ] شخص محدد يستقبل الملاحظات والأعطال خلال الأسبوع الأول
