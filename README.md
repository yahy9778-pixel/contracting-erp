# نظام إدارة شركة المقاولات

نظام ويب عربي يغطي المسار الذي يدخل منه المال: **العقد وجدول الكميات ← التقرير اليومي للموقع ← اعتماد الكميات ← مستخلص المالك**، مع صلاحيات لكل دور ووكيل ذكي للتقرير اليومي.

## ما يعمل الآن

| الوحدة | ماذا تفعل |
| --- | --- |
| المستخدمون والصلاحيات | 6 أدوار (المالك، مدير مشروع، مهندس موقع، العقود، المالية، التخطيط). كل مستخدم يرى مشاريعه فقط. مهندس الموقع لا يرى الأسعار ولا المستخلصات. |
| المشاريع | بيانات العقد: المالك، الاستشاري، القيمة، المدة، نسبة المحتجز، الدفعة المقدمة، الضريبة. |
| جدول الكميات (BOQ) | إضافة بنود أو لصقها مباشرة من Excel، وربط كل بند برمز تكلفة (D1..D11، E1..E4، F1..F3). يعرض المنفذ ونسبة الإنجاز لكل بند. |
| التقرير اليومي | العمالة، المعدات، الكميات المنفذة لكل بند، المعوقات. دورة: مسودة ← رفع ← اعتماد مدير المشروع أو رفضه. |
| وكيل التقرير اليومي | يلصق المهندس رسالة الموقع كما هي (نص حر)، فيحولها الوكيل إلى مسودة تقرير مطابقة لبنود BOQ. ما لا يطابق بندا يظهر في المعوقات ولا يُخمَّن. لا يعتمد شيئا بنفسه. |
| مستخلصات المالك (IPC) | تُحسب تلقائيا من الكميات المعتمدة فقط: السابق، الحالي، التراكمي، المحتجز، استرداد الدفعة المقدمة، الضريبة، الصافي. دورة: مسودة ← رفع للاستشاري ← اعتماد (بالمبلغ المعتمد) ← تحصيل. قابل للطباعة PDF. |
| لوحة المشاريع | قيمة العقد، المنفذ المعتمد، نسبة الإنجاز، التقارير المعلقة، آخر مستخلص. |
| سجل التدقيق | كل إنشاء أو اعتماد أو حذف يسجل في AuditLog، وكل تشغيل للوكيل يسجل في AgentAction. |

## المرحلة الثانية (مضافة)

| الوحدة | ماذا تفعل |
| --- | --- |
| الجودة: طلبات الاستلام (IR) | تسجيل طلب الاستلام للبند والموقع والكمية، ثم نتيجة الاستشاري. في المشاريع التي تشترط الاستلام لا تدخل الكمية المستخلص إلا بعد اعتماد الـ IR. رفض الاستلام يفتح NCR تلقائيا. |
| الجودة: عدم المطابقة (NCR) | تسجيل ومتابعة حتى الإغلاق بإجراء تصحيحي مكتوب، مع تنبيه عند تجاوز موعد الإغلاق. |
| المكتب الفني | الـ Submittals (مواد، مخططات تنفيذية، طرق تنفيذ) بإصداراتها وردود الاستشاري A/B/C/D، والاستفسارات الفنية RFI مع مواعيد الرد. |
| المشتريات | طلب شراء من الموقع، اعتماد مدير المشروع، تسجيل عروض الموردين ومقارنتها، أمر شراء من العرض المختار (اختيار غير الأقل يحتاج سببا مكتوبا)، واعتماد المالك لما فوق حد الصلاحية (50,000 افتراضيا، يُغيّر بـ `PO_APPROVAL_LIMIT`)، ثم الاستلام الجزئي أو الكامل. لا يُرفع طلب لمادة مرتبطة بـ Submittal غير معتمد. |
| مقاولو الباطن | عقد باطن بتخصص D1..D11 وبنود من جدول الكميات بسعر الباطن، مع هامش الربح لكل بند. مستخلص الباطن لا يقبل كمية أكبر مما استلمه الاستشاري منا للبند نفسه. |
| التنبيهات | لكل مشروع قائمة "ما يحتاج متابعة": المتأخر والمعلق في كل الأقسام، وعددها يظهر في لوحة المشاريع. |

## المرحلة الثالثة: المالية والتخطيط (مضافة)

| الوحدة | ماذا تفعل |
| --- | --- |
| دليل الحسابات والقيود الآلية | دليل حسابات لشركة مقاولات (نقدية، عملاء، محتجزات، موردون، مقاولو باطن، دفعات مقدمة، ضريبة، إيرادات، تكاليف حسب النوع). كل حدث معتمد يرحّل قيده وحده في نفس المعاملة: اعتماد مستخلص المالك (إيراد، ذمة، محتجز، استرداد دفعة مقدمة، ضريبة)، تحصيله، استلام المواد (تكلفة على رمز التكلفة ومستحق للمورد)، اعتماد مستخلص الباطن ودفعه، المصروفات، والسندات. الحدث لا يُرحَّل مرتين. |
| القيود اليدوية | للتسويات والرواتب ورأس المال والإفراج عن المحتجزات. لا يُقبل قيد غير متوازن، والقيود لا تُحذف بل تُعكس بقيد مقابل. |
| ميزان المراجعة وكشوف الحسابات | للشركة كلها أو لمشروع، مع كشف حساب بالرصيد الجاري لكل حساب. |
| السندات والأرصدة | سند صرف لمورد (لا يتجاوز المستحق له على المشروع)، سند قبض للدفعة المقدمة (لا يتجاوز المتبقي في العقد)، وأرصدة الموردين ومقاولي الباطن والعملاء لكل مشروع. |
| مصروفات الموقع | تُسجل برمز تكلفة وضريبة ومن أي صندوق أو بنك، وتُحمَّل على تكلفة المشروع فورا. |
| خطابات الضمان | ابتدائي، حسن تنفيذ، دفعة مقدمة، محتجز. تنبيه قبل الانتهاء بـ 30 يوما، مع التمديد والإفراج. |
| الموازنة وضبط التكاليف | موازنة لكل رمز تكلفة، مقابل الملتزم به (أوامر الشراء وعقود الباطن والمصروفات) والفعلي (المرحّل محاسبيا) والمتوقع عند الانتهاء، مع تنبيه عند التجاوز. وقائمة دخل المشروع وهامش الربح. |
| الجدول الزمني | أنشطة بتواريخ وأوزان، تُنشأ من جدول الكميات بضغطة. إنجاز النشاط المرتبط ببند يأتي من التقارير اليومية المعتمدة تلقائيا. المخطط مقابل الفعلي، مؤشر SPI، حالة كل نشاط، ومنحنى S. |
| التدفق النقدي | توقع 6 أشهر من الجدول الزمني والموازنة: الصرف في شهر التنفيذ، والتحصيل بعد شهر بعد المحتجز والدفعة المقدمة، مع تنبيه إذا صار رصيد المشروع سالبا. |

الصلاحيات الجديدة: المالية والمالك فقط يرون الحسابات العامة ويرحّلون القيود والسندات. مدير المشروع يسجل مصروفات الموقع. المخطط والمالك يضعون الموازنة. المخطط ومدير المشروع يعدّلون الجدول. مهندس الموقع يرى الجدول الزمني ولا يرى شيئا ماليا، ولا تظهر له التنبيهات المالية.

## التشغيل محليا

المتطلبات: Node.js 20 أو أحدث.

```bash
npm install
cp .env.example .env        # ثم ضع قيمة عشوائية طويلة في SESSION_SECRET
npm run setup               # ينشئ قاعدة البيانات ويضيف بيانات تجريبية
npm run dev                 # افتح http://localhost:3000
```

حسابات تجريبية (كلمة المرور لكلها `Demo@12345`، غيّرها قبل أي استخدام فعلي):

| البريد | الدور |
| --- | --- |
| owner@company.local | المالك / الإدارة العليا |
| pm@company.local | مدير مشروع |
| site@company.local | مهندس موقع |
| contracts@company.local | العقود والمستخلصات |
| finance@company.local | الإدارة المالية |
| qc@company.local | الجودة QA/QC |
| technical@company.local | المكتب الفني |
| procurement@company.local | المشتريات ومقاولو الباطن |
| planning@company.local | التخطيط وضبط التكاليف |

لتفعيل الوكيل الذكي ضع مفتاح Claude API في `ANTHROPIC_API_KEY` داخل `.env`. الوكيل يستخدم نموذج `claude-opus-5-5` مع إعادة محاولة تلقائية على نموذج بديل إذا رُفض الطلب.

## التقنية

Next.js 15 (واجهة وخادم في تطبيق واحد) · TypeScript · Prisma · Tailwind · Claude API.
قاعدة البيانات SQLite للتجربة؛ للتشغيل الفعلي غيّر `provider` في `prisma/schema.prisma` إلى `postgresql` وضع رابط PostgreSQL في `DATABASE_URL`.

## ملاحظات وحدود

- الكمية القابلة للمستخلص = الأقل من (المنفذ في التقارير المعتمدة، والمستلم في طلبات الاستلام المعتمدة). يمكن إلغاء شرط الاستلام لمشروع معين عند إنشائه.
- المبالغ محفوظة كأرقام عشرية مع تقريب لأقرب هللة؛ عند الانتقال إلى PostgreSQL يُفضل تحويلها إلى Decimal.
- أوامر الشراء بدون ضريبة؛ الاستلام يثبت المستحق للمورد بقيمة الأمر. فواتير الموردين ومطابقتها مع الاستلام (3-way match) لاحقا.
- لا يوجد بعد إقفال فترات محاسبية ولا قوائم مالية رسمية (مركز مالي، دخل للشركة). الإفراج عن المحتجزات يُسجل بقيد يدوي.
- الجدول الزمني بلا علاقات تتابع بين الأنشطة (Critical Path). منحنى الفعلي يحسب الأنشطة المرتبطة ببنود تاريخيا، واليدوية بنسبتها الحالية فقط.
- لا توجد بعد: المخازن، الموارد البشرية والرواتب، المعدات والورشة. هذه في المرحلة الرابعة مع وكلاء الأقسام الذكية.
